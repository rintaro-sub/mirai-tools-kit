# 学生チーム【運営】ポータル

政策立案・企画・広報・エンジニア・事務局・役員会の6部門をつなぐ、vanilla JavaScriptの運営ポータルです。実行時の外部ライブラリ、CDN、外部通信はありません。参照元は同じ作業環境の `policy-planning-tool-oss/public/` です。ES Modules、`renderX(el)`、共通CSSクラス、SVGアイコン、共通関数のインターフェースを踏襲しています。

## 起動

```sh
python3 -m http.server 8000 --directory public --bind 127.0.0.1
```

`http://localhost:8000/` を開きます。ES Modulesを使うため、HTMLのダブルクリックではなくHTTPサーバーから開いてください。サブディレクトリ配信にも対応しています。

## 使い方

ヘッダーの「表示メンバー」で自分を選択し、部門ナビゲーションから各ツールを開きます。表示メンバーは操作確認用の切替であり、認証・権限制御ではありません。戻る・進むはブラウザ履歴に対応します。

- **ポータル `#/`**：今週のMTG数・完了タスク・期限超過・自分の未読通知、自分の未完了タスク、MTGの準備状態、全部門の状態とリンクを表示。タスクを押すと期限・優先度・状態を更新できます。通知は表示メンバーごとに既読にできます。
- **政策立案 `#/policy`**：議題を追加し、相談中・決定・却下を変更。賛成・反対は一人一票で、同じボタンを押すと解除します。コメント、担当・期限付きのタスク化、日時・出席者・議題・決定事項付きの定例議事録作成と決定のタスク化ができます。
- **企画 `#/kikaku`**：名前・説明・担当・期限付きの企画を追加。立案・進行・レビュー・完了を変更し、タブで絞り込みます。
- **広報 `#/koho`**：X・Instagram・noteの原稿を追加・編集。Unicodeのコードポイント数でX 140字、Instagram 2200字を上限とし、noteは無制限。上限超過の保存・レビュー依頼を防ぎます。下書き→レビュー→承認→公開予定と進み、差し戻しでは理由を記録。承認時は `approvals` に記録します。カレンダーは承認済み・公開予定だけを週単位で表示します。SNSへの自動投稿は行わず、公開は各サービスで実施してください。
- **エンジニア `#/engineer`**：優先度・担当・ラベル付きIssueを追加し、未着手・進行・完了を変更。完了IssueからMarkdownのリリースノートを生成し、表示欄から選択してコピーできます。
- **事務局 `#/jimu`**：文書のタイトル・カテゴリ・本文を検索。文書を追加・編集し、通知文・議事録・企画書の雛形を本文末尾へ挿入できます。FAQは折りたたみ表示です。
- **役員会 `#/yakuin`**：面談メモを追加し、担当・期限を決めてタスク化。全部門の相談中議題を集約し、全部門のタスク完了率を確認・更新できます。

タスク化は元データにタスクIDを保存します。再試行時は元データIDでも重複を検出します。保存に失敗したときはダイアログを維持し、エラーを表示します。

## ファイル構成

```text
public/                  # 正本。アクションボードへの移植対象
  index.html             # 共通ヘッダー・ナビ・描画領域
  style.css              # 全CSS・テーマ変数・スマホ対応
  js/
    app.js               # ルーター・共通関数・ダイアログ
    icons.js             # 参照元と同じSVGアイコン実装
    store.js             # スキーマ・初回seed・localStorage読み書き
    views/
      home.js
      policy.js
      kikaku.js
      koho.js
      engineer.js
      jimu.js
      yakuin.js
scripts/build.js         # public/ → static/・docs/への配布
static/                  # 既存ホスティング向け生成物
docs/                    # GitHub Pages向け生成物
tests/check.js           # 全JSの構文チェック
tests/portal.test.js     # jsdom上で実際のES Modulesを実行するDOMテスト
```

`static/`・`docs/` は直接編集せず、`npm run build` で更新してください。旧 `policy.html` などのURLには新しいHashルートへの転送ページを生成します。旧単一HTMLダッシュボードのテスト `tests/verify.cjs`・`tests/weekly.cjs` は過去実装向けで、現行の `npm test` の対象ではありません。

## データと集計

保存キーは `mirai.portal.store`、スキーマは `version: 1`。共通エンティティは `members`・`projects`・`tasks`・`meetings`・`documents`・`agendas`・`approvals`・`minutes`・`issues`・`faqs`・`notices` です。すべてのレコードに `id`・`dept`・`title`・`status`・`created_at`・`updated_at` を持たせています。タスク・MTGには要求された追加項目を持たせています。

初回だけ、日本時間の起動日を基準に、各部門12件以上の架空データを生成します。日付はリロードで移動しません。今週は日本時間の月曜〜日曜。MTG数は予定日、完了タスク数は `completed_at`、期限超過は「未完了かつ期限が今日より前」で集計します。部門カードのタスク数は未完了件数、進行中PJは状態が「進行」の件数です。未読通知は `read_by` に表示メンバーが含まれない通知数です。

データはこのブラウザ・同一オリジンだけに保存されます。チームの別端末には同期されません。共同運用のサーバー認証・API接続は別途必要です。複数タブでの同時編集は避けてください。削除やブラウザデータ消去の前には、開発者ツールでこのキーのJSONを控えてください。初期化にはこのキーだけを削除して再読み込みします。旧データキーは移行・変更しません。不正JSON・未対応バージョン・保存領域利用不可の場合、元データを上書きせず一時データで表示し、変更はエラーにします。

## カスタマイズ・アクションボードへの移植

- 色は `public/style.css` 冒頭のCSS変数で管理。カードは黒1px枠・角丸12px、ボタンはピル型・最小44pxです。フォントは端末の日本語フォントを使用します。600px以下で縦積み、入力は16pxです。
- 初回データは `store.js` の `seed()` を編集。既存保存データには自動でseedを追加しません。
- 部門の画面は `views/` 内の `renderX(el)` を編集。共通関数は `app.js` からimportします。
- `api(path, { method, body, keepalive })` の呼び出し形式を参照元と揃えています。ローカル版は `GET` で参照、`POST` で追加、`PATCH` で更新します。`keepalive` はローカル同期保存のため不要です。実APIへ移植する際はこのアダプターを置換します。
- `esc`・`state`・`todayStr`・`fmtDate`・`avatar`・`jstDateTime` は参照元と同じ呼び出し形式です。参照元への統合時はこれらを `lib.js` のimportへ置き換え、既存のルート・認証・DBスキーマと統合してください。このリポジトリから参照元ファイルは変更していません。

## 検証

開発用にNode.js 22以降とnpmを用意します。jsdomはテストだけの依存で、配布サイトは依存しません。

```sh
npm install
npm run check
npm test
npm run build
```

テストはseedの共通フィールドと部門件数、ポータル、通知既読、タスク更新、投票切替、コメントのHTMLエスケープ、議題・議事録・面談のタスク化、企画追加・絞り込み・状態変更、広報の文字数・差し戻し・承認・週移動、Issue追加・Markdown生成、文書検索・雛形挿入、履歴バック、未知ルート、メンバー切替、再読み込み、不正データ保護を検証します。

実装環境では利用可能なNodeと既存jsdomで構文・DOMテストを実行し、合格しました。390pxのメディアクエリと縦積み指定は検証していますが、描画ブラウザがないため実画面の目視確認は未実施です。
